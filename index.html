Sheet 3 of 6 · Architecture decision recordsThe trade-offs behind the numbers

Four decisions that mattered more than the model

Each one started from a constraint the business could name, and each has a measurable consequence.

ADR-001Knowledge

Retrieval over fine-tuning for knowledge

Context
Manuals and procedures change weekly, and safety audits require every answer to point to its source.
Decision
Agentic RAG with hybrid search and cross-encoder re-ranking. Fine-tuning is used only for style and terminology, never for facts.
Result
Updates go live on re-index, not retraining, and every answer carries citations.
ADR-002Cost

Route each query to the cheapest model that can answer it

Context
About 65% of questions were routine lookups that did not need a frontier model.
Decision
A router sends routine queries to Claude Haiku or a LoRA-tuned Llama 3 8B, complex ones to Claude Sonnet; 8-bit quantisation and a semantic cache sit in front.
Result
Cost per query down ~30% with no regression on the evaluation suite. The tuned 8B model matched Sonnet on terminology lookups at about a fifth of the cost.
ADR-003Quality

Make evaluation a release gate, not a report

Context
Prompt and model changes were shipping without a shared definition of "good enough".
Decision
A ~500-case suite (RAGAS plus LLM-as-judge for groundedness, relevance and safety) runs in CI/CD. Nothing ships below 0.85 groundedness.
Result
Unsupported answers fell from ~12% to under 4%.
ADR-004Governance

Security and data rules built into retrieval

Context
Business, IT-security and data-governance teams all had to sign off before production.
Decision
PII redaction with Bedrock Guardrails, role-based document filtering at retrieval time, in-region data residency, and an approved Azure OpenAI pattern as a second platform.
Result
Production sign-off from all three groups, and a reference pattern reused across the program.
